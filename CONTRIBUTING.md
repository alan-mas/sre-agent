# Contributing

Run `make hooks` once after cloning. It sets `core.hooksPath=.githooks` (a
`commit-msg` hook that validates every message and a `pre-push` hook that flags
commits to squash), `commit.template=.gitmessage` (a guide shown when you run
`git commit` without `-m`) and `rebase.autoSquash=true`.

## Commits

- **One logical change per commit.** Do not mix refactors, formatting and behavior
  changes; tests pass after every commit, so `git bisect` stays useful.
- **Prompt, model, retrieval or tool changes** carry their eval evidence in the body
  (accuracy, cost, latency before/after), per the project rules.
- Fixup commits (`git commit --fixup <sha>`) are fine while iterating; squash them
  (`git rebase --autosquash`) before merging.

## Squash before you push

A commit is one self-contained logical change that ships with its tests and docs
([Google](https://google.github.io/eng-practices/review/developer/small-cls.html),
[Linux](https://docs.kernel.org/process/submitting-patches.html),
[Django](https://docs.djangoproject.com/en/dev/internals/contributing/committing-code/)).
Clean up local history before sharing it; never rewrite pushed commits
([git-rebase](https://git-scm.com/docs/git-rebase)).

| Squash (one change) | Keep separate (different changes) |
|---|---|
| A fix, typo or review tweak to an unpushed commit | A refactor and the feature built on it |
| Docs or tests for a change you just committed | A bug fix and an unrelated feature |
| A revert of an unpushed commit (drop both) | Independent changes that each stand alone |
| Same `type(scope)` on the same files | Changes that are already pushed |

While iterating, commit fixes with `git commit --fixup <sha>`; `make hooks` sets
`rebase.autoSquash`, so `git rebase -i origin/main` folds them in.

The `pre-push` hook checks only unpushed commits:

| Level | When | Effect |
|---|---|---|
| `error` | `fixup!`/`squash!`/`amend!` commits left | blocks: autosquash first |
| `squash` | a commit reverts, repeats (`type(scope)` + files) or documents/tests an earlier unpushed one (mentions its files or the ids it added, e.g. `D41`) | blocks; `SQUASH_OK=1 git push` to push as is |
| `consider` | consecutive `docs`/`chore` commits | hint only |

## Commit messages

Based on [Conventional Commits 1.0](https://www.conventionalcommits.org/en/v1.0.0/)
and the 50/72 rule from [git-commit](https://git-scm.com/docs/git-commit#_discussion).

```
<type>(<scope>)!: <summary>

<body: why the change is needed, what was wrong before, what changes>

<trailers>
```

| Part | Rule | Enforced |
|---|---|---|
| type | `feat` `fix` `perf` `refactor` `test` `eval` `docs` `build` `ci` `chore` `revert` | error |
| scope | optional, lowercase kebab-case: `agents` `alerts` `budget` `cli` `deps` `evals` `graph` `hooks` `infra` `k8s` `lab` `llm` `middleware` `postmortem` `prompts` `rbac` `scenarios` `slack` `tools` | error if malformed, warning if new |
| `!` | breaking change; the body must explain the migration | error without a body |
| summary | imperative ("If applied, this commit will _&lt;summary&gt;_"), lowercase start, no trailing period, at least two words, not vague (`update`, `wip`, `fix`) | error |
| header length | aim for 50 characters, hard limit 72 | warning / error |
| blank line | between header and body, and before trailers | error |
| body | wrap at 72 (URLs and indented code are exempt); explain *why*, not *how* | error |
| body required | `feat`, `fix`, `perf`, `refactor`, `revert` and any breaking change (at least 20 characters) | error |
| trailers | `Refs: #12`, `Fixes: #12`, `BREAKING CHANGE: <description>` (uppercase), `Co-authored-by: Name <email>` | error on lowercase `BREAKING CHANGE` |

Messages generated by git (`Merge ...`, `Revert "..."`) and `fixup!`/`squash!`/`amend!`
commits pass through unchanged.

### Examples

```
fix(tools): cap pod log output at TOOL_MAX_CHARS

get_pod_logs returned the full log and pushed noisy pods past the
context window, so the commander dropped earlier evidence. Truncate
from the head and keep the last lines, where crashes are reported.

Eval (crashloop subset, 3 runs): accuracy 2/3 -> 3/3, cost -38%.

Refs: #14
```

```
docs: document the HITL approval flow
```

Avoid: `Updated stuff`, `fix bug`, `WIP`, `Fixed the tool.`, `feat: Add Retries`.

### Checking a message by hand

```
python scripts/check_commit_msg.py .git/COMMIT_EDITMSG
```

If a commit is rejected, the message stays in `.git/COMMIT_EDITMSG`; fix it and run
`git commit -e -F .git/COMMIT_EDITMSG`. The hook is local and can be bypassed with
`--no-verify`; reserve that for emergencies.
